# 01 · 愿景与定位

## 一句话定位

**把复杂的开源 AI 世界,变成开发者可以一键自托管、完全拥有的私有 AI 平台。**

> Own your stack —— 跑在你自己的硬件上,数据与推理不出你的边界,没有 SaaS 锁定。

## 我们要解决的问题

今天想拥有一个私有、本地、懂自己资料的 AI,你必须自己拼装一整条链路:

- 模型选型(Qwen? Llama? 多大参数? 什么量化?)
- 硬件与运行环境(GPU、VRAM、CUDA、Docker、驱动)
- RAG(解析、切片、Embedding、向量库、检索)
- 微调(LoRA、数据集格式、训练参数)

如果你还想把它做成能交付给**非技术用户**的产品,就得再从零建一遍产品底座:账号、鉴权、引导向导、聊天界面、部署与运维护栏。

Build My AI 把这两层都做成一个**零依赖、可自托管、开源**的平台。开发者部署它,就直接拥有整条链路——从「选型 + 引导安装」到「账号 / RAG / API」——而且全程数据留在自己的机器上。

## 设计哲学

1. **自托管优先(own your stack)** —— 一条命令跑在你自己的机器/服务器;数据与推理默认不出边界,云是显式选择。
2. **零依赖** —— 后端纯 Python 标准库、前端零构建原生 JS:没有 `pip install`、没有打包器、没有供应链要审计。
3. **隐私红线由测试强制** —— 全站只有一个文件可联网、自由文本一律拒收且不落日志、身份与遥测分库;违反即 CI 变红(见 [19 安全模型](19-security-model.md))。
4. **开箱即用的成品** —— 平台自带一个面向非技术终端用户的**参考产品**(营销站 + 傻瓜向导 + 聊天演示 + 账号中心)。你可以直接部署给你的用户用,或把它当作自己产品的起点。
5. **诚实** —— 界面与文档绝不宣称代码给不了的能力。

## 四阶段愿景(平台的能力阶梯)

这条阶梯既是平台提供给**开发者**的 API / 模块,也是**参考产品**呈现给终端用户的体验。

### 第一阶段:把 AI 装起来

需求 → 检测设备 → 推荐方案 → 引导安装。终端用户在 20~30 分钟内拥有一个能用的本地 AI;开发者拿到的是 `/v1/advise` 顾问端点 + 客户端生成的安装方案(install-my-ai.bat + 手册 + 机读 install-plan.json)。

### 第二阶段:把资料交给 AI

拖入 PDF、Word、Excel、邮件,AI 基于这些资料回答问题(RAG),答案带来源。

### 第三阶段:让 AI 越来越了解用户

通过 Memory 和 Teach My AI 持续收集「AI 回答 → 用户修改 → 正确答案」,数据足够后自动 LoRA / 微调。

### 第四阶段:让 AI 真正替用户完成工作

通过 API 和工具接入,AI 连接软件与工作流,从「回答问题」进化到「完成任务」。

## 最终形态:两个受众,一套平台

- **开发者 / 自托管者**:`git clone` → 一条命令自托管(见 [SELF-HOSTING.md](../SELF-HOSTING.md))→ 拥有一个完整、可扩展、可嵌入自己应用的私有 AI 平台,数据全程自持。
- **终端用户**(在开发者部署的参考产品里):不需要选「Qwen 还是 Llama」,只需要选——

  - 「我要一个**采购 AI**。」
  - 「我要一个**公司知识 AI**。」
  - 「我要一个**研究 AI**。」

  然后点击:

## **Build My AI**
