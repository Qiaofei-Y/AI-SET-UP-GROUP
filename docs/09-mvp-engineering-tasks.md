# 09 · MVP 工程任务清单

> 对应 [04 MVP 范围](04-mvp.md)。目标:Windows + NVIDIA,普通人 30 分钟内拥有本地 AI。
> 任务编号规则:`M<里程碑>-<序号>`。估算单位为人日(1 人全职一天),按 1 名全栈 + 1 名后端的小团队假设。

## 里程碑总览

| 里程碑 | 名称 | 验证目标 | 估算合计 |
|--------|------|----------|----------|
| M0 | 技术骨架与选型验证 | 关键技术路径全部跑通(手动) | ~10 人日 |
| M1 | 一键安装与推理跑通 | 双击安装器 → 模型能回答问题 | ~18 人日 |
| M2 | 方案顾问与对话 UI | 检测设备 → 推荐方案 → 网页对话 | ~14 人日 |
| M3 | RAG 知识库 | 拖入 PDF → 基于文档回答并给出来源 | ~16 人日 |
| M4 | API、埋点、打包与 Beta | 可分发的签名安装包 + 真实用户实测 | ~14 人日 |

**关键路径**:M0 → M1 → M2 → M3 → M4,总计约 72 人日(2 人约 2 个月,含缓冲)。

## M0 · 技术骨架与选型验证(先手动跑通,再谈自动化)

> 参考:M0-2(llama.cpp + OpenAI 兼容流式接口)和 M0-3(Embedding → 检索 → 来源引用)对应的技术路径,已在开发机(macOS,llm-lab 栈)上跑通一套可运行的参考实现,并接入了演示站聊天页 —— 见 [16 本地 AI 接入网页](16-local-ai-web-integration.md)。Windows + NVIDIA 环境仍需按下表逐项验证。

| ID | 任务 | 验收标准 | 依赖 | 估算 |
|----|------|----------|------|------|
| M0-1 | 确定技术栈:安装器框架(Tauri vs Electron vs 原生 NSIS+WebView2)、推理运行时(llama.cpp server vs Ollama 内嵌)、UI 框架 | 写成 ADR(架构决策记录)入库,含理由和放弃项 | — | 2 |
| M0-2 | 手动验证推理路径:在一台 Windows + NVIDIA 机器上手动跑通 llama.cpp(或选定运行时)+ 一个 GGUF 模型 + OpenAI 兼容接口 | curl 能拿到流式回答;记录 tokens/s | M0-1 | 2 |
| M0-3 | 手动验证 RAG 路径:选定 Embedding 模型 + 向量库(Chroma/Qdrant 二选一),手动跑通 PDF → 切片 → 索引 → 检索 | 对 3 个真实 PDF 提问,检索命中正确段落 | M0-1 | 3 |
| M0-4 | 精选模型清单 v1:按 VRAM 档位(6/8/12/16/24GB)选定 5~10 个模型 + 量化档位,核对 License 允许商用再分发 | 每个模型有:HF 下载链接、SHA256、VRAM 实测占用、tokens/s 实测、License 结论 | M0-2 | 2 |
| M0-5 | 建仓库工程化:monorepo 结构、CI(GitHub Actions,Windows runner)、代码规范 | push 触发构建;README 有开发环境搭建文档 | M0-1 | 1 |

**M0 出口条件**:所有关键技术路径在开发机上手动跑通过一遍,没有"到时候再看"的未知项。

## M1 · 一键安装与推理跑通

### 设备检测

| ID | 任务 | 验收标准 | 依赖 | 估算 |
|----|------|----------|------|------|
| M1-1 | 硬件检测模块:CPU 型号/核数、RAM、GPU 型号、VRAM、磁盘剩余空间 | 在 5 种不同 NVIDIA 显卡上输出正确;无 GPU 时明确报告 | M0-5 | 2 |
| M1-2 | 环境检测模块:Windows 版本、NVIDIA 驱动版本、是否满足运行时最低要求 | 驱动过旧时给出人话提示 + 指向 nvidia.com 美国官网下载页 | M1-1 | 1 |
| M1-3 | 不支持设备的礼貌出口:AMD/Intel GPU、无 GPU、VRAM < 6GB 的提示页(收集邮箱等 Phase 1) | 明确告知原因,不让用户装到一半失败 | M1-1 | 1 |

### 下载与安装

| ID | 任务 | 验收标准 | 依赖 | 估算 |
|----|------|----------|------|------|
| M1-4 | 模型下载器:从 Hugging Face(美国 CDN)下载,支持断点续传、进度显示、SHA256 校验 | 手动断网重连后能续传;校验失败自动重下 | M0-4 | 3 |
| M1-5 | 运行时安装:内嵌预编译的推理运行时(含 CUDA 依赖),无需用户装 Python/CUDA Toolkit | 干净的 Windows 11 虚拟机上装完即可运行 | M0-2 | 3 |
| M1-6 | 本地服务管理:推理服务的启动/停止/开机自启/崩溃自动重启,端口冲突自动换端口 | 杀掉进程后 10 秒内自动拉起;端口被占用时无感切换 | M1-5 | 2 |
| M1-7 | 安装器外壳:欢迎页 → 检测 → (临时:手动选模型)→ 下载 → 安装 → 完成页,全程进度和人话说明 | 非技术用户不看文档能走完;每步失败有"重试"按钮 | M1-2, M1-4, M1-5 | 4 |
| M1-8 | 失败诊断 v1:磁盘不足、驱动过旧、下载失败、杀毒软件拦截四大场景的检测与人话提示 | 每个场景有对应的错误页 + 解决指引 | M1-7 | 2 |

**M1 出口条件**:干净的 Windows 机器上,双击安装器 → 完成页 → 本地 API 能回答 "hello",全程无命令行。

## M2 · 方案顾问与对话 UI

### 方案顾问(规则版,不是 AI)

| ID | 任务 | 验收标准 | 依赖 | 估算 |
|----|------|----------|------|------|
| M2-1 | 需求模板:3~5 个预设场景(公司知识 AI / 写作助手 / 通用助手…)+ 自由文本框(MVP 先映射到最近模板) | 用户选模板或打一句话都能进入下一步 | — | 2 |
| M2-2 | 推荐引擎 v1:规则表 `(场景, VRAM 档位) → (模型, 量化, RAG 开关)`,数据来自 M0-4 实测 | 任意检测结果都有唯一推荐 + 一个备选;规则表是数据文件不是硬编码 | M0-4, M1-1 | 3 |
| M2-3 | 方案展示页:用人话展示推荐(“质量/速度/占用空间”三个维度),隐藏所有技术名词,提供"高级模式"折叠层给懂的人看细节 | 10 个非技术用户看懂率 ≥ 8 | M2-2 | 2 |

### Web UI

| ID | 任务 | 验收标准 | 依赖 | 估算 |
|----|------|----------|------|------|
| M2-4 | 对话界面:流式输出、Markdown 渲染、会话历史(本地存储)、新建/删除会话 | 与本地推理服务联通,首 token 延迟可见即流式 | M1-6 | 4 |
| M2-5 | 状态页(Control Center 雏形):当前模型、显存/内存占用、服务状态、重启按钮 | 数据实时刷新;重启后自动恢复 | M1-6 | 2 |

**M2 出口条件**:全流程 = 描述需求 → 看到人话方案 → 点安装 → 打开界面对话。

## M3 · RAG 知识库

| ID | 任务 | 验收标准 | 依赖 | 估算 |
|----|------|----------|------|------|
| M3-1 | 文档解析:PDF(含扫描件先不做 OCR,明确提示)、Word、Excel、TXT/Markdown | 20 个真实样本文件解析成功率 ≥ 90%,失败有人话提示 | M0-3 | 3 |
| M3-2 | 切片与索引管线:智能切片(按标题/段落)→ Embedding(英文优化模型,本地运行)→ 向量库写入 | 100 页 PDF 索引 < 2 分钟(在 M0-4 基准机上) | M3-1 | 3 |
| M3-3 | 检索与注入:向量检索 top-k → 拼入 prompt → 回答;无相关内容时明确说"资料里没有" | 基于文档的 20 个测试问题,答案正确率人工评 ≥ 80% | M3-2 | 3 |
| M3-4 | 来源引用:回答下方显示"来自《xxx.pdf》第 n 页",点击可查看原文片段 | 每条引用可追溯到具体切片 | M3-3 | 2 |
| M3-5 | 知识库管理 UI:拖拽上传、文件列表、索引状态(排队/处理中/完成/失败)、删除文件即删索引 | 拖 10 个文件同时上传不卡死;删除后提问不再引用 | M3-2, M2-4 | 3 |
| M3-6 | 增量与一致性:重复上传去重;同名文件更新时重建该文件索引 | 更新文件后旧内容不再出现在回答里 | M3-5 | 2 |

**M3 出口条件**:拖入公司 PDF → 提问 → 得到带来源的正确回答。

## 横切事项(贯穿所有里程碑)

- **日志**:所有组件写统一格式的本地日志,错误页有"复制诊断信息"按钮 —— Beta 排障的生命线。
- **测试机矩阵**:至少覆盖 6GB / 8GB / 12GB VRAM 三档 + Windows 10/11;每个里程碑出口在全矩阵上过一遍。
- **术语审查**:每个面向用户的文案合并前检查一遍,不允许出现 VRAM、量化、Embedding、token 等词。
- **埋点先行**:M4-2 的事件定义在 M1 就要确定,各模块边开发边埋,不要最后补。

## 建议执行顺序(2 人分工)

```
第 1-2 周   M0 全部(两人一起,选型必须共识)
第 3-5 周   A:M1 安装器/下载/服务    B:M2 顾问规则表 + Web UI
第 6 周     联调 M1+M2,里程碑验收
第 7-8 周   A:M3 解析/索引/检索      B:M3 知识库 UI + M4 API
第 9 周     A:M4 埋点/打包/签名      B:横切事项收尾 + 测试矩阵
第 10 周    Beta 实测与报告
```
