# 03 · 核心模块

平台由六大核心模块组成,对应用户旅程的每个环节。

## 模块一:AI 方案顾问(Advisor)

**职责**:把用户的自然语言需求翻译成技术方案。

输入维度:

- **用途**:知识问答 / 写作 / 编程 / 数据分析 / 客服 …
- **预算**:现有设备 / 愿意买硬件 / 愿意付云费用
- **隐私**:必须本地 / 可以云端 / 混合
- **速度**:实时对话 / 可以等待
- **用户数量**:个人 / 小团队 / 全公司

输出:推荐模型 + 量化方案 + 硬件要求 + RAG 方案 + 是否需要微调 + 本地/云端建议。

## 模块二:自动部署系统(Auto-Deploy)

**职责**:把方案变成一个能跑的系统,全程无需用户操作命令行。

- 检测 CPU、GPU、RAM、VRAM、系统环境、驱动版本、磁盘空间
- 自动安装:推理运行时、模型权重、RAG 组件、Web UI、API 服务
- 安装过程可视化:进度、预计时间、每一步在做什么(人话)
- 失败自动诊断:驱动过旧、空间不足、端口占用等 → 给出一键修复

## 模块三:AI Control Center

**职责**:安装完成后,用户管理一切的 UI。

| 管理对象 | 能力 |
|----------|------|
| 模型 | 切换、更新、删除、查看占用 |
| 知识库 | 添加/删除文档、查看索引状态 |
| API | 开关、密钥管理、用量查看 |
| Memory | 查看/编辑 AI 记住的内容 |
| 工具 | 接入/断开外部工具和软件 |
| 运行状态 | 显存/内存占用、速度、日志(人话版) |

## 模块四:Knowledge / RAG

**职责**:让 AI 能基于用户自己的资料回答问题。

- 用户操作只有一个:**拖入文件**(PDF、Word、Excel、邮件、纯文本…)
- 系统自动完成:格式解析 → 智能切片 → Embedding → 向量索引 → 检索 → 引用溯源
- 回答时显示来源:"这个答案来自《2024采购合同.pdf》第 3 页"
- 增量更新:文件改了,索引自动跟着更新

## 模块五:Teach My AI

**职责**:让 AI 越用越准。这不是"把文档拿去微调"。

核心循环:

```
AI 回答 → 用户修改/确认 → 记录 (问题, 错误回答, 正确答案)
       → 数据积累到阈值 → 自动 LoRA / Fine-tuning → 模型更新
```

- 反馈收集零负担:用户只是正常纠正 AI,系统在后台积累训练数据
- 数据够了才微调,不够时先用 RAG + Few-shot 兜底
- 微调前后自动对比评测,效果不提升不上线

## 模块六:Model Registry

**职责**:平台的"模型情报库",持续跟踪主流开源模型。

每个模型记录:

- 版本与更新历史
- License(能否商用)
- 硬件要求(各量化档位的 VRAM/RAM 需求)
- 能力画像(英文、长文本、推理、代码、工具调用…)
- 下载来源与校验(Hugging Face 等美国主流托管源,走美国 CDN)
- 与各推理运行时的兼容性

Registry 是**方案顾问的知识来源**:顾问推荐的每一个方案都基于 Registry 中的实测数据,而非猜测。
