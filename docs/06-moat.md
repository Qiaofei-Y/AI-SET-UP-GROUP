# 06 · 为什么这套方法持久有价值:AI Deployment Intelligence

> 本项目是免费开源、面向 AI 爱好者与开发者的。这一章不谈商业竞争,只谈:为什么「需求 → 方案」这件事值得长期打磨,以及它靠什么越用越好。

## 真正的价值不在哪

- ❌ 不在 Ollama —— 任何人都能封装一个安装器
- ❌ 不在某一个开源模型 —— 模型每几个月就换代,谁都能下载
- ❌ 不在 UI —— 界面可以被抄

这些都是会过时、可替换的部分。

## 真正持久有价值的是什么

一个持续进化的映射:

```
什么用户 + 什么任务 + 什么数据 + 什么预算 + 什么硬件
                        ↓
        = 什么模型和部署方案效果最好
```

我们称之为 **AI Deployment Intelligence**。模型会换、运行时会换,但「在 8GB 显存上跑英文合同问答该选什么模型 + 什么量化」这类经验,是跨模型、跨时代都用得上的知识。把它沉淀下来,顾问端点(`/v1/advise`)就能给每个用户越来越准的建议。

## 这些经验从哪里来

平台的每一次使用都可以(在用户 opt-in 的前提下)沉淀出可复用的经验:

| 环节 | 沉淀出的经验 |
|------|------------|
| 需求选择 | 人们真实想用 AI 做什么(需求分布) |
| 设备检测 | 大家手里有什么硬件(硬件分布) |
| 自动安装 | 什么组合能装成功、什么组合会失败(兼容性地图) |
| RAG 使用 | 什么切片/Embedding 方案对什么文档效果好 |
| Teach My AI | 什么任务上模型答错了什么(能力边界实测) |
| 微调 | 什么数据量 + 什么方法带来多少提升 |

作为开源项目,这些沉淀属于社区:任何人都能看到、复现、改进推荐规则(见 [installer/](../installer/) 与 registry 的钉版策略)。

## 正向循环

```
更多人用 → 更多真实部署经验 → 推荐方案更准 → 安装成功率更高、效果更好 → 更多人愿意用并回馈
```

新模型发布时,只看 benchmark 很难知道它在 8GB 显存的英文合同问答场景里到底行不行;有真实部署的实测经验,推荐就能落到实处。

## 对产品的要求

从第一天起就要把「推荐→结果」的经验以结构化方式沉淀(匿名、opt-in、可关闭,见 [19 安全模型](19-security-model.md)):

1. 每次推荐方案的输入(需求/硬件)和输出(方案)
2. 安装结果:成功/失败/失败原因
3. 使用质量信号:用户纠正、点赞点踩、会话时长
4. 方案变更:用户从推荐方案换到了什么

**这些数据结构的设计优先级,等同于产品功能本身。** 遥测默认关闭、纯匿名,红线由测试强制。
