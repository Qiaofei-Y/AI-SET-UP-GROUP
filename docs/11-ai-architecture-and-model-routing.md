# 11 · AI 架构与模型路由

> 回答一个核心问题:"Choose Your Need 该连什么 AI?能不能用云端模型省钱?"
> 结论:平台里有**两个不同的 AI**,别混为一谈。

## 两个 AI,别混淆

| | ① 方案顾问大脑(Advisor Brain) | ② 用户最终用的 AI(Deployed AI) |
|---|---|---|
| 干什么 | 读懂需求 → 推荐模型/硬件/RAG 方案 | 用户天天拿来问自己资料 |
| 什么时候跑 | 只在安装配置时跑一次 | 装好后长期、高频使用 |
| 跑在哪 | **平台的云端(Claude API)** 或 MVP 的规则表 | **默认用户本地**,可选云端 |
| 涉及隐私吗 | 否(用户只描述需求,未上传资料) | 是(要读用户的私密文档) |

"Choose Your Need 连什么 API"问的是 ①;"用云端省费用"落在 ②。

## ① 方案顾问大脑

**推荐:云端 Claude API。** 理由:

- 这一步用户只描述需求("我想要一个采购 AI"),**不涉及隐私**,发云端没问题。
- 只在安装时跑一次,**每用户成本几分钱**,不值得自建。

模型选择:

| 任务 | 推荐模型 | 说明 |
|------|----------|------|
| 意图分类 / 结构化提取 | `claude-haiku-4-5` | 便宜、快,适合把"我想要 X"映射到场景枚举 |
| 听懂模糊需求 + 权衡硬件 | `claude-opus-4-8` 或 `claude-sonnet-5` | 需要真正推理时用 |

**MVP 阶段可以先不接 AI**:方案顾问 v1 用规则表 `(场景, VRAM 档位) → 方案`(见 [09 工程任务清单](09-mvp-engineering-tasks.md) M2-2)。零 API 成本,够验证产品假设。有量后再上 Claude 让它能处理自由文本。

## ② 用户最终用的 AI:本地默认 + 云端可选

"用云端省费用"的关键是**省谁的费用**:

| 方案 | 用户成本 | 隐私 | 适合 |
|------|----------|------|------|
| 本地部署 | 一次性买硬件,之后每次问答免费 | 最高,数据不出设备 | 有显卡、重隐私 |
| 云端调用 | 零硬件投入,按用量付费 | 数据出设备 | 无显卡 / 不敏感 / 想先试 |

**成本临界点**:本地 = 先付硬件、边际成本≈0;云端 = 零首付、按次付费。用得越多越久,本地越划算。

**隐私硬约束**:公司知识 AI 等场景**默认必须本地**("私有"就是卖点)。云端必须是**用户显式选择**,并明确提示"数据会离开这台电脑"。

## 对商业模式的意义

云端选项不只是便利功能,它就是商业模式里的**云 GPU 收入线**(见 [05 商业模式](05-business-model.md)):用户设备不够时,平台提供云端算力并抽成。所以"云端调用"是**必须做的第二条路**,排在 MVP 之后(见 [07 路线图](07-roadmap.md) Phase 1)。

## 数据流与隐私边界(一张图说清)

```
安装配置阶段(可上云):
  用户需求文本 ──→ ① 方案顾问(Claude API / 规则表)──→ 推荐方案
  ⚠️ 只发"需求描述",绝不发用户文档

使用阶段(默认不出设备):
  用户文档 ──→ 本地 RAG ──→ ② 本地模型 ──→ 回答
                              └─(用户显式选云端时)─→ 云 GPU
```

**红线**:用户的**文档内容**在任何情况下都不随 ① 上云;埋点(见 [06 护城河](06-moat.md))也只收集硬件档位/方案/成败,**不含任何文档内容**。

## 最终愿景衔接

第四阶段"让 AI 连接软件替用户干活"会用到 **Claude 的工具调用 / Agent 能力**(Tool Use、MCP)。届时 ② 可以从"本地开源模型答问题"升级为"编排工具完成任务",本地模型负责隐私敏感部分,复杂 Agent 推理可路由到云端 Claude——同样遵守上面的隐私红线。
